# Contributing

Thank you for your interest in contributing to KineticAI-AWGC. The repository is maintained as a reproducible research asset; contributions are expected to uphold the same standard.

## Scope

KineticAI-AWGC integrates experimental datasets, mechanistic kinetic modeling, and machine-learning baselines for spray-pyrolyzed apatite–wollastonite glass-ceramics. Contributions may include:

- corrections or extensions to the datasets (with documented provenance);
- improvements to the analytical notebooks or the `src/` modules;
- additional validation, tests, or documentation;
- reproducible figures and results summaries.

## Workflow

1. Fork the repository and create a descriptive branch.
2. Implement the change with clear, concise commit messages written in the past tense.
3. Ensure the change satisfies the repository standards below.
4. Open a pull request against `main` and describe the scientific rationale and the expected effect.

## Repository Standards

### Reproducibility

- All notebooks must execute successfully, top to bottom, on a fresh environment built from `requirements.txt`.
- Every committed result (datasets, parameters, figures) must be regenerated by the committed code. If a change alters a result, regenerate the corresponding assets and commit them together.
- Notebooks should be executed before submission so that their outputs are embedded and current.

### Data Integrity

- Phase fractions must sum to 100 % within published rounding (tolerance 0.06).
- Derived datasets must contain no missing values and no duplicate rows.
- Any transcription from the source publications must be recorded in `data/README.md` together with its provenance.

### Validation

- The test suite must pass: `python -m pytest tests/ -v`.
- The automated validation workflow (`.github/workflows/validate.yml`) must complete successfully; it is executed automatically for every pull request.

### Style

- Code should follow the conventions of the existing modules, with docstrings in the NumPy style.
- Documentation and commit messages should use precise, academic language: formal register, complete sentences, and no promotional phrasing.

## Reporting Issues

When reporting an issue, please include the relevant dataset or notebook, the observed behavior, and the expected behavior. Reproducibility concerns should reference the specific validation step that failed.
